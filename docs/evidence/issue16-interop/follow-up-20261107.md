# Issue #16 GateD 互通补验

2026-11-07，RHEL 10.2 aarch64，Linux 6.12.0-211.49.1.el10_2，SELinux Enforcing。
基线 main 为 0cfcf6a。复用 aarch64 RPM 0.1.1-0.2.devbb070e0.el10，核对
bb070e0 与基线的 EGP C/H 源和 FRR 补丁无差异。GateD 使用同一份 3.6 移植构建，
来源、许可与前期移植过程见 [初次记录](README.md)。

## 原生双向转发

四个独立 namespace 分别承载 egpd/Zebra、GateD 和两个端点。两台路由器经
198.18.168.0/24 相连，端点是 10.16.0.2/8 与 172.16.16.2/16。两端点各用
本侧路由器作默认网关。两台路由器均启用 IPv4 forwarding，GateD 的链路和
stub 接口均为 bridge。GateD 禁用 RIP，使用 export metric 1 和邻居 importdefault。
本轮 GateD 启用内核写入，两边都有学习路由，跨两台路由器的 ICMP 探测双向通过。

| 场景 | egpd | GateD | 结果 |
| --- | --- | --- | --- |
| AS 65001 ↔ 65002 | active，配置 2/6，协商 30/120 | passive，通告 30/120，内部调度 32/128 | 双向装表和端点探测通过 |
| AS 65002 ↔ 65001 | passive，配置和协商 45/180 | active，通告 30/120，内部调度 47/188 | 双向装表和端点探测通过 |

线上的 Request/Confirm 带协商最小值。两个实现用不同的内部发送间隔，GateD 为
最小间隔预留了余量。双方都宣告可用两种模式时，小 AS 选 active。另用独立原始
报文对端分别发送 Confirm status 1 和 2，egpd 分别进入 passive 和 active 后到 Up。
主动对端先发了不同 AS 的 Confirm，再以正确 AS 完成建邻。RFC 904 §4.1.3 要求
至少一侧 active，GateD 与 egpd 的默认能力通告会自动选出互补角色。

## 撤路和恢复

原生会话删除 egpd 的 network 后，GateD 收到匹配的省略 Update，随后从内核删除
10.0.0.0/8。恢复 network 后，两侧转发恢复。分别由 egpd 删除邻居和由 GateD
退出触发 Cease，抓包看到两侧 Cease code 3/status 5。GateD 回 code 4/status 0，egpd 回
code 4/status 5，两侧清表，再建邻后恢复转发。

GateD 重载出口策略会重新发 Request 并重置邻居。在初次试验中，metric 255 和
省略策略都触发了这条路径，不能用该次掉路判定 Update 的语义。独立报文对照保留
原生的 AS、公共网和当前 Poll 序号。两端只替换 solicited Update，重算 EGP
校验和。接收侧的 namespace 内过滤原帧，放行用 DSCP CS1 标记的替换帧。
Hello、Poll、Acquire 和 Cease 原样通过。恢复时删除该过滤和替换条件。

- **显式撤路**：两侧各接受一个匹配 Poll 的距离 255 Update，内核均清除对端
  stub 前缀，邻居保持 Up。恢复正常通告后双向转发恢复。
- **连续遗漏**：对 egpd 发三个匹配 Poll 的零网关 Update，前两次观察到 misses
  1 和 2，第 3 次清除路由。GateD 在收到第一个有效遗漏 Update 时即清除路由。
  恢复正常通告后双方装表，端点再次双向通过。
- 从开始显式撤路到第二次恢复转发，抓包没有 Acquire 类报文。所有报文的 EGP
  校验和均通过独立复核。抓包与过滤计数保留了原始 Update 和替换 Update。

## 实现和规范观察

- 非请求 Update 的发送 R 与接收 S 在短窗口内可不同。GateD 对不匹配的报文
  执行 RFC 904 §4.1.1 的丢弃建议，匹配的 solicited Update 仍能安装路由。
- GateD 在一次接受的 Update 未列出旧前缀时即清除该前缀。egpd 为每个候选
  维护遗漏计数。显式距离 255 与连续遗漏是分开的输入。
- 历史 GateD 的接收选项 importdefault 是这套环境收进 10.0.0.0/8 的配置条件。
  开启写内核的结果限定于本轮 bridge 拓扑与移植构建。旧的 -n 实验只检查 GateD RIB。
- GateD 在独占 namespace 内写过自身的 loopback 路由。原实验和宿主路由不在
  该命名空间内。

原始规范 [RFC 904 §4](https://www.rfc-editor.org/rfc/rfc904.html#section-4)、
[RFC 888](https://www.rfc-editor.org/rfc/rfc888.html)。抓包可解压后用同目录的
decode_egp_pcap.py 独立解码。先前实验的配置、结果和适用范围保留在原记录。
