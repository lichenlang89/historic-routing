### 本轮发现并修掉的两个实现问题（都是实测暴露的，不是看出来的）

1. **Poll 超频判定打断 RFC 904 §4.4 的合法流程**：`unsolicited_updates()` 用例靠"同一序列号的
   重复 Poll"消耗主动更新预算，最初的实现在 Poll 上也做超频判定，直接让该用例超时。
   现在 Poll 不做超频判定，超频 Error 只对 Hello 生效（`docs/FIDELITY.md` 已写明原因）。
2. **阈值的两个数值错误**：`EGP_MAX_INTERVAL` 起初取 86400（16 位字段根本到不了，Refuse 永不触发），
   改为 3600；Hello 超频阈值 `hello/2` 在 `hello=1` 时为 0，改为 `max(1, hello/2)`。

## lab.sh reload（S9.5）

同一份实验、`LAB_TIMERS` 默认 2/6：

```
PASS 重载新增一条 network：egpd pid 不变、邻居不抖、原有路由保留
PASS 同配置二次重载幂等（frr-reload 报无变化，pid 不变）
PASS 恢复原配置：只撤掉新增网络，原路由与邻居保持
```

过程中确认的 frr-reload 用法（写进 `lab/egp/test_reload.py` 的注释）：
`frr-reload.py` 在 `sbin/`；必须给 `--bindir`/`--confdir`（默认 `/usr/bin`、`/etc/frr` 会直接报错）；
要在 rundir（默认 `/var/run/frr`）写临时文件；喂给它的必须是**完整**运行配置，
只给 `egp` 行会让它把 `hostname` 等行判成待删。

`frr-reload --test` 的 dry-run 输出（手工核对用）：

```
Lines To Add
============
egp network 192.168.0.0
```

即 frr-reload 认识 egpd 的配置行，把它当成普通 daemon 处理。
