# Issue #16 长期链路与多邻居验收

2026-11-07，RHEL 10.2 aarch64，Linux 6.12.0-211.49.1.el10_2，SELinux Enforcing。
基线 main 为 0cfcf6a，复用 0.1.1-0.2.devbb070e0.el10 的 Zebra 和 egpd，EGP C/H
及 FRR 补丁与该基线一致。场景仅使用独占 namespace 和独立套接字目录。

## 多邻居容量和稳定性

一台 egpd/Zebra 通过隔离 bridge 与独立原始报文对端相连。分批从 1、2、4、8 扩到
16 邻居。每个对端用不同 AS，在同一份 Update 中为两条不重叠的 /16 分别通告自身
和第三方下一跳。逐条比较邻居候选、Zebra 路由和内核下一跳。

- **容量**：16 邻居、32 条路由，第 17 个配置命令的 egpd VTY 状态为 13
  （CMD_WARNING_CONFIG_FAILED）。配置和路由快照保持 16/32。
- **稳定性**：16 邻居持续 180 秒，每 5 秒核对全部前缀和下一跳。两个对端注入
  旧序列号和同一 Poll 的重复响应，探针前缀未进入邻居候选或内核。
- **并发恢复**：四个对端同时以距离 255 撤路，再次发布恢复。另选四个对端
  连续遗漏，老化后恢复。再同时终止四个对端，确认只清除其对应八条路由，
  重启后恢复 32 条。最终同时删除 16 个邻居，留下 0 条 EGP 内核路由。
- **首轮失败**：首个 fixture 没有等待独立对端监听，错过第一轮 Acquire。
  增加握手时发现参数漏传，修正后 1→16 通过。最初预期第 17 个命令输出警告
  文本，vtysh 没有显示该文本，随后改用 egpd 的 UNIX VTY 返回值及 RIB/FIB
  快照判断，并保留原失败。没有修改 egpd 或放宽 16 邻居、32 条路由的断言。

## 60 分钟固定种子丢包与乱序

两台 egpd/Zebra 用 198.18.166.0/24 相连，Hello/Poll 为 2/6 秒。每端各通告
一个 stub 前缀。对两个 veth 的出方向依次应用 1%、5%、10% 随机丢包，
各 1,200 秒。每阶段延迟为 80 ms ± 35 ms，乱序 20%、相关性 50%。
阶段 1/2/3 的两侧种子依次为 16010/16011、16020/16021、16030/16031。

| 丢包 | 样本 | A/B 路由存在样本 | A→B / B→A 探测通过 | UDP 乱序 / 实收 |
| --- | ---: | --- | --- | --- |
| 1% | 40 | 40 / 40 | 39 / 39 | 899 / 992 |
| 5% | 40 | 40 / 40 | 38 / 37 | 826 / 951 |
| 10% | 39 | 35 / 36 | 28 / 27 | 781 / 893 |

每约 30 秒采样一次。UDP 每阶段单独发送 1,000 个连续序号报文，收到的序号低于此前
最大值即计为一次乱序。UDP 数据说明实际发生了乱序。10% 丢包阶段出现短时掉路，
采样结果反映该条件下的恢复能力和可用性。60 分钟结束后将两侧丢包设为 100%，
观察到两邻居 Down、学习路由清空。撤掉规则后邻居重新 Up、路由重新安装，
两方向探测均恢复。自施加全断链到确认恢复共约 19 秒，其中含清表观察和探测时间。

每阶段在有效 Poll 回复之后分别注入一个陈旧序号和一个已消费序号的 Update。
抓包确认两种探针均抵达接收端，updateRx 计数未增，探针前缀没有进入内核。
独立重传实验中，无应答 Request 原序号重发间隔 30.027 秒。过滤第一条 Cease-ack 后，
Cease 原序号重发间隔 29.991 秒，最终释放邻居槽位并恢复双向探测。
丢失的常规 Poll 回复由后续带新序号的 Poll 补进度。

采样期间，两个 egpd 各保持 14 个打开的文件描述符。RSS 范围分别为
6,600–6,696 KiB 和 6,596–6,692 KiB。CPU 累计增加 65 和 59 个 tick
（100 tick/s）。本轮未观察到 RSS 或 FD 持续增长。运行时间为 60 分钟，
覆盖这套小规模拓扑和固定种子。

阶段探针由 transient unit 启动时，UDP bind 返回 Permission denied。
保留该次失败，随后通过 SSH 登录上下文运行两个探针，长时间测试持续运行。
Wireshark 首次以 root 执行时 Lua 自定义字段未注册，切换非特权用户后 51 个样本通过。
