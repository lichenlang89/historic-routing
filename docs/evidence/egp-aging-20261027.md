# RFC 888 遗漏老化回归，2026-10-27

全新 aarch64/Fedora 42 构建的 verify 结果为
13 PASS / 1 KNOWN-FAIL / 0 SKIP / 0 FAIL；14 项已知上游失败未变。
codec/策略单测在 ASan/UBSan 下通过。

独立原始报文测试逐份响应本机 Poll，验证结果：

```text
PASS first two omissions retain the route
PASS reappearance resets omission history
PASS third consecutive omission withdraws from RIB and kernel
PASS explicit 255 still withdraws on the first Update
```

每次有效遗漏响应都会刷新 last_update，因而第三次撤路不能由旧路由超时冒充。
单测另验证重新出现后的 distance 0、显式撤路与新增网络混合、重复网络拒绝和容量上限。
此前的可达性/控制状态回归与 Update 场景保留；空 Update 场景改为检查连续三次后的老化，
显式 distance 255 的及时撤路断言保持不变。

策略依据 RFC 888 §5 的“多次遗漏”要求，三次是本实现选择，不是 RFC 指定常量。
